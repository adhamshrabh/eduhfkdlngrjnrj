# منصّة الروضة

منصّة تعليمية موحّدة: محرّك قصص تفاعلية + استوديو تأليف + ألعاب + دفتر صف + لوحة إدارة.
مبنية بدمج مشروعَي `educational-activity-engine` و `APP_WE` في هيكل واحد.

---

## التشغيل السريع

### بلا Docker (تطوير)

```bash
# ١) الباك إند
cd backend
python -m venv .venv && source .venv/bin/activate   # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                 # ثم عدّلي القيم
python manage.py migrate
python manage.py seed_demo                           # حسابات تجريبية
python manage.py runserver 8000

# ٢) الواجهة (طرفية ثانية)
cd frontend
npm install
npm run dev            # التطبيق  → http://localhost:5173
npm run dev:studio     # الاستوديو → http://localhost:5174
```

**حسابات `seed_demo`** — غيّري كلمات المرور قبل أي نشر:

| الدور | البريد | كلمة المرور |
|---|---|---|
| مديرة | `admin@rawda.local` | `admin12345` |
| معلّمة | `muallima@rawda.local` | `teacher12345` |

### بـ Docker (إنتاج)

```bash
export DJANGO_SECRET_KEY="قيمة-عشوائية-طويلة"
export POSTGRES_PASSWORD="كلمة-مرور-قوية"
export DJANGO_ALLOWED_HOSTS="srv1714868.hstgr.cloud"
docker compose up -d
```

خدمة واحدة تخدم كل شيء: الواجهة والاستوديو والواجهة البرمجية ولوحة Django. وهي تستمع على `127.0.0.1:8000` لا على الشبكة — الباب منهٍ عكسي.

### HTTPS ليس خياراً هنا

قارئ البطاقات يمرّ عبر Web Serial، والمتصفّح يحذف `navigator.serial` كلّياً في «السياق غير الآمن». قياسٌ على خادم الروضة، بالمتصفّح نفسه:

| العنوان | `isSecureContext` | `navigator.serial` |
| --- | --- | --- |
| `http://187.127.118.191:8888` | `false` | `undefined` |
| `https://srv1714868.hstgr.cloud` | `true` | `object` |

فالفرق ليس في المتصفّح ولا في الكبل: هو العنوان وحده. ونشرُ المنصّة على منفذٍ عارٍ ولو «مؤقّتاً» يعني صفّاً بلا بطاقات.

**الخادم الحالي فيه nginx وشهادة Let's Encrypt صالحة** على `srv1714868.hstgr.cloud`، فلا يلزم إصدار شهادة:

```bash
sudo cp deploy/nginx-rawda.conf /etc/nginx/conf.d/rawda.conf
grep -rl srv1714868.hstgr.cloud /etc/nginx/   # عطّلي كتلة «Coming Soon» القديمة
sudo nginx -t && sudo systemctl reload nginx
```

ثم أغلقي المنفذ 8888 من الجدار الناري: بابٌ ثانٍ بـ http يعني معلّمةً تفتحه بالخطأ فلا تعمل بطاقاتها.

على خادمٍ جديد بلا nginx، `deploy/Caddyfile` يقوم بالدور نفسه بشهادة تلقائية (ويكفي اسم `nip.io` بلا شراء نطاق).

## استيراد قصصك الحالية

```bash
cd backend
python manage.py import_stories \
  --source "/path/to/educational-activity-engine/content/stories" \
  --owner muallima@rawda.local \
  --dry-run          # تقرير أولاً، بلا كتابة

# ثم بلا --dry-run، وأضيفي --publish لنشرها مباشرة
```

الأمر **لا يلمس ملفاتك المصدرية** — يقرأ وينسخ فقط، ويطبع مقارنة قبل/بعد لكل قصة
(عدد المشاهد وعدد الأصول) حتى لا يمرّ استيراد ناقص بصمت.

## قرارات معمارية (ولماذا)

### ١. المحرّك بقي TypeScript خالصاً

PixiJS يرسم على `<canvas>` بشجرة عرض خاصة به — لا يمكن أن يصبح مكوّنات React.
ما يفعله React هنا ثلاثة أشياء فقط: يوفّر عنصر DOM مضيفاً، يُشغّل ويُنهي المحرّك،
ويستمع إلى `EventBus`. لا يقرأ حالته الداخلية ولا يستدعي دواله.

النتيجة: **567 اختباراً في المحرّك عملت يوم الدمج بلا تعديل حرف واحد** فيها
(وهي اليوم 918 بعد أنواع النشاط الجديدة).

الجسر كلّه في `apps/web/src/features/player/useEngine.ts` — ملف واحد.

### ٢. الاستوديو بقي كما هو

`StudioApp.ts` (142 كيلوبايت) ومنطق الحفظ ذو الطبقتين لم يُمسّا. بدل إعادة كتابتهما،
يعترض `editorApiBridge.ts` نداءات `/__editor/*` ويترجمها إلى `/api/stories/`.
النتيجة: **504 اختبار في الاستوديو عملت يوم الدمج بلا تعديل** (وهي اليوم 688)،
ومنطق السقوط على التخزين
المحلي عند انقطاع الشبكة يبقى عاملاً كما صُمِّم.

> هذه طبقة انتقالية معروفة لا تصميم نهائي. عند إعادة بناء الاستوديو بـ React
> لاحقاً، ينادي `/api/stories/` مباشرة ويُحذف هذا الملف.

### ٣. Django يخدم المسارات القديمة أيضاً

المحرّك يقرأ من `/content/stories/<slug>/story.json` — عقد مُثبَّت في `StoryLoader`
و`AssetUrls`. بدل تعديلهما، يخدم Django المسارات نفسها من قاعدة البيانات
(`apps/stories/compat_views.py`)، و`story.json` يعود **حرفياً كما حُفظ** بلا إعادة
كتابة لمسارات الأصول.

ما اختفى بنيوياً بهذا الترحيل — مشاكل عانيت منها فعلاً:

| المشكلة القديمة | لماذا لم تعد ممكنة |
|---|---|
| تباين `public/content` مقابل `content/` | لا مرآة أصلاً — مصدر واحد |
| الحفظ في قصّة خاطئة | الـ slug من المسار + فحص المالك في الخادم، بلا أي قيمة افتراضية بديلة |
| «المسارات غير موجودة خارج `vite dev`» | خادم واحد في التطوير والإنتاج |
| كتابة معلّمتين فوق بعضهما | حقل `version` يرفض الحفظ القديم برسالة واضحة |

### ٤. لا حسابات للأطفال

الروضة تعرض على شاشة واحدة أمام الصف — لا جهاز لكل طفل. فلا هوية فردية، ولا
تتبّع تقدّم فردي، ولا نقاط ولا أوسمة ولا لوحة صدارة. التقدّم يُسجَّل على مستوى
الصف في دفتر الصف. وهذا أيضاً يعني **صفر بيانات شخصية عن الأطفال** في القاعدة.

### ٥. وضع العرض ميزة أولى لا ثانوية

خط بحجم 72/44 بكسل يُقرأ من آخر الغرفة، ملء شاشة حقيقي، إخفاء كامل للواجهة،
ومنع الشاشة من النوم أثناء العرض (`WakeLock`).

## ما هو داخل هذه النسخة وما هو مؤجَّل

**داخلها:** مصادقة (معلّمة/مديرة) · القصص + المشغّل + وضع العرض · الاستوديو ·
الألعاب · الصفوف ودفتر الصف · لوحة إدارة (داخل التطبيق + Django Admin) · PWA
مع تخزين مؤقت للعمل بلا إنترنت.

**مؤجَّل صراحةً:** EduBot · توليد الدروس بالذكاء الاصطناعي · TTS · YOLO ·
CameraRunner · Unity WebGL · لوحة وليّ الأمر · بنك الأسئلة · الواجبات · ESP32/RFID
(الكود منقول ومعطّل) · Redis · Celery.

كل بند مؤجَّل، لا ملغى — النماذج مصمّمة لتستقبله بلا هدم.

## أنواع الأنشطة — ثمانية، ولكلٍّ ورقته

النشاط هو ما يفعله الطفل في المشهد. والأنواع تُسجَّل في `ActivityRendererRegistry`
وحده: **إضافة نوعٍ جديد نداءُ `register()` لا تعديلٌ في أي مشهد**.

| النوع | يسأل | الرقعة |
|---|---|---|
| `drag-match` | الحرف الناقص في كلمة | v1.0 |
| `pick-correct` | أيّ الصور؟ | v1.0.10 |
| `card-answer` | ما البطاقة التي تُجيب؟ (فضاء مفتوح) | [v1.0.20](./docs/Scene-Model-Specification-v1.0.20.md) |
| `sequence` | بأي ترتيب؟ | [v1.0.22](./docs/Scene-Model-Specification-v1.0.22.md) |
| `jigsaw` | أين تعود هذه القطعة؟ (تحويل مكاني) | [v1.0.25](./docs/Scene-Model-Specification-v1.0.25.md) |
| `sort` | ما الذي يجمع هذه الأشياء؟ (تصنيف) | [v1.0.26](./docs/Scene-Model-Specification-v1.0.26.md) |
| `find` | أين هو؟ (لغة مكانية في المشهد نفسه) | [v1.0.27](./docs/Scene-Model-Specification-v1.0.27.md) |
| `all-respond` | ما رأي الصفّ كلّه؟ (بطاقات استجابة) | [v1.0.28](./docs/Scene-Model-Specification-v1.0.28.md) |

وأن يبقى الطرفان متّفقين يحرسه اختبار: `apps/studio/src/ActivityTypeParity.test.ts`
يسقط إن سُجِّل نوعٌ في المحرّك بلا محرّرٍ في الاستوديو — أو العكس. وهو العطل
الصامت الوحيد في هذه الطبقة: النوع يعمل في المشغّل تماماً، ولا يُرى إلّا حين تفتح
المعلّمة المشهد فتجد شارة «نوع لا تتوفّر واجهة تحرير له».

ولكلٍّ منها **سندٌ بحثيّ مكتوب، وحدودُ ذلك السند**، في
[`docs/Activity-Evidence-Base.md`](./docs/Activity-Evidence-Base.md). القاعدة التي
تُتَّبع في النوع التاسع: الفجوة أوّلاً، ثم الورقة، ثم الحقل — وما لا يُسنَد إلى
شيءٍ خارج ذوقنا يُكتب هناك بوصفه حدساً.

### القصّة المرجعية

```bash
cd backend && python manage.py seed_yara_finds
```

تبذر «يارا تبحث عن أغراضها» (`yara_finds`): ثمانية مشاهد تمرّ على **ستّة أنواع
نشاط**، بأصولٍ منسوخة من قصصٍ قائمة — بلا رسمٍ جديد. الأمر متكرّر الأمان.

وهي مكتوبة لتُفتح في الاستوديو لا لتُشغَّل فقط: كل مشهد من الثمانية يجب أن يعرض
محرّر نشاطه، لا شارة «نوع لا تتوفّر واجهة تحرير له». وهذا أسرع فحصٍ يكشف أن
نوعاً جديداً سُجِّل في المحرّك ونُسي في الاستوديو.

## الألعاب — ملاحظة على الجرد

جرد فعلي لمشروع `APP_WE` كشف أن «سبع ألعاب» ليست سبع ألعاب:

| الأصل | الحقيقة | القرار |
|---|---|---|
| `OsmoTangram` | لعبة كاملة، وضعا شاشة وكاميرا | ✅ منقولة — لعبة الأساس |
| `OsmoNewton` | تتطلّب كاميرا + TensorFlow | ✅ منقولة، تظهر عند وجود كاميرا |
| `GestureMath` | تتطلّب كاميرا + TensorFlow | ✅ منقولة، تظهر عند وجود كاميرا |
| `SubwayRunner` | ليست لعبة — `<iframe>` لبناء Unity (17 ميغا) + محادثة تنادي `localhost:5000` | ⏸ مؤجّلة مع Unity والمحادثة |
| `OsmoGames` | قائمة لا لعبة | ⏸ استُبدلت بسجلّ `registry.ts` |
| `CameraRunner` · `YoloDetector` | كاميرا + خدمة YOLO على الخادم | ⏸ مؤجّلتان |

كل لعبة تُحمَّل كسولاً، وتُخفى تلقائياً إن لم يدعمها الجهاز، وترسل نتيجتها إلى
`POST /api/games/sessions/` عبر عقد `GameModule` واحد — لا مسار خاص بكل لعبة.

**خطأ أُصلح أثناء النقل:** `OsmoNewton.tsx` كان يستخدم `RefreshCw` بلا استيراده —
كان سيتعطّل وقت التشغيل عند عرض زرّ التحميل.

## أعطال وُجدت بالتشغيل الحيّ (لا بمراجعة الكود)

أربعة منها ما كان أي اختبار وحدة ليمسكها — ظهرت فقط عند تشغيل المنصّة فعلياً
في متصفّح والنقر فيها:

| العطل | الأثر لو بقي | الإصلاح |
|---|---|---|
| المُتحقِّق يفترض المشاهد في جذر `story.json` | **رفض استيراد كل قصة حقيقية** — المشاهد فعلياً في `story.scenes`، والجذر يحمل معرّفات نصية | `extract_scene_objects()` تقرأ الموضعين، ويستخدمها المُتحقِّق و`scene_count` والاستيراد معاً |
| `/content/stories/index.json` يعيد كائنات | `discover()` يمرّر كل عنصر إلى `load(id)` مباشرة → `load("[object Object]")` → لا تُحمَّل أي قصة | يعيد مصفوفة معرّفات نصية |
| مسار SPA يبتلع `/studio/assets/*` | **الاستوديو صفحة بيضاء تماماً** — الأصول تصل كـ text/html فيرفضها المتصفّح بلا رسالة مفهومة | تُخدَم أصول الاستوديو قبل المسار الشامل |
| مسار SPA يبتلع `registerSW.js` و `sw.js` | PWA لا تعمل إطلاقاً — العمل بلا إنترنت معطّل بصمت | `RootAssetView` يخدم ملفات جذر Vite بنوعها الصحيح |
| صلاحية بلا `has_permission` | **قائمة القصص مكشوفة لأي زائر** بلا تسجيل دخول | صلاحية صريحة + استعلام فارغ للزوّار |
| `RefreshCw` مستخدم بلا استيراد (كودك الأصلي) | تعطّل وقت التشغيل عند ظهور زرّ التحميل في OsmoNewton | أُضيف الاستيراد |

بند مفتوح مقصود: زرّ «← القائمة» الذي يرسمه المحرّك داخل اللوحة يبقى ظاهراً في
وضع العرض. إخفاؤه يعني تعديل المحرّك، وقرارنا كان ألّا نلمسه في هذه المرحلة.
